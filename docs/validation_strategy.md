# Validation strategy

## 1. 랜덤 CV 대신 rolling-origin

예측 대상은 미래 시즌입니다. 랜덤 분할은 같은 시즌의 선수 상태와 환경을 학습·검증에
동시에 포함해 실제 배포 성능을 과대평가할 수 있습니다.

검증 시즌 `Y`마다 다음 규칙을 사용했습니다.

```text
train: season < Y
valid: season == Y
```

모델, 선수 사전, 보정기와 앙상블 가중치 모두 이 시간 경계를 지켜야 합니다.

## 2. 개발과 확인 분리

- 과거 시즌에서 모델과 가중치를 결정
- 다음 시즌에서 개발 게이트 확인
- 마지막 시즌에서 한 번만 고정 확인
- 확인 결과를 본 뒤 같은 후보의 강도나 gate를 다시 조정하지 않음

실제 연구 후반에는 2025가 2024 레짐의 연장일 수 있다는 가설도 별도 lane으로
측정했습니다. 이는 보편적인 연도 전이 증거와 구분해 보고했습니다.

## 3. 평균 성능 외 안정성

단일 Brier 차이만으로 승격하지 않고 다음을 함께 확인했습니다.

- 연도별 Brier delta
- 월별 개선 방향
- 시즌 전반/후반 pooled delta
- 선수 단위 clustered bootstrap 개선확률
- 기존 모델과의 잔차 상관 및 블렌드 순증분

## 4. 행 독립성

평가 행끼리 정보를 공유하지 않는지 다음 조건에서 같은 행의 예측을 비교했습니다.

- 전체 batch와 singleton
- 서로 다른 batch size
- 행 순서 shuffle 후 복원
- 다른 행 추가·제거

이 저장소의 `pitch_control.invariance`는 그 핵심 검사를 합성 데이터로 재현합니다.
